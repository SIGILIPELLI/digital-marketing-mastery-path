# 02 · Topic Clusters & Content at Scale

Ranking for one keyword is a tactic; owning a whole topic is a strategy. **Topic clusters** organise content so search engines (and readers) see you as the authority on a subject. This module shows how to plan, produce and maintain content at scale without losing quality.

## 1. Pillar and cluster model

1. A **pillar page** covers a broad topic comprehensively: "Office Catering: The Complete Guide for Indian Companies".
2. **Cluster pages** go deep on subtopics: "Office catering cost per head", "Healthy snacks for meetings", "Diwali corporate gifting food", "GST on catering services".
3. Every cluster page links to the pillar, and the pillar links to every cluster page, using descriptive anchors.
4. Clusters capture long-tail searches; the pillar gains authority from all of them.

## 2. Build the cluster map

1. Start with the pillar keyword and collect 30–100 related queries (Keyword Planner, People also ask, Search Console, competitor content).
2. Group queries by **intent** — if Google shows the same top results for two queries, they belong on one page; if results differ, they need separate pages.
3. Plan the URL structure: `/office-catering/` (pillar) and `/office-catering/cost-per-head/` etc.
4. Prioritise clusters with business value first (commercial intent), then supporting informational ones.

## 3. Produce content at scale with quality

1. Create **content briefs** for every page: target query, intent, outline (H2/H3), questions to answer, unique angle or data, internal links, word-count guide, CTA.
2. Use templates for recurring formats (comparison pages, city pages, how-to guides) — but fill each with genuinely specific information.
3. Use AI tools for research, outlines and first drafts if you like, then add expertise, examples, real numbers and editing. Google's guidance targets **scaled content created mainly to manipulate rankings**, regardless of how it's made — mass-produced pages with little value can be demoted.
4. Have a subject expert review accuracy; add author bios with credentials.

## 4. Maintain and prune

1. Quarterly **content audit**: export pages with clicks, impressions and key events (Search Console + GA4).
2. **Update** pages that are slipping (refresh data, add sections, improve intros).
3. **Merge** thin or overlapping pages into stronger ones with 301 redirects.
4. **Remove or noindex** pages with no value and no traffic.
5. Track cluster performance as a group — total clicks to the cluster, rankings of the pillar.

## Cheat sheet

| Element | Purpose |
|---|---|
| Pillar page | Broad, comprehensive hub |
| Cluster page | Deep answer to one subtopic |
| Internal links | Cluster ↔ pillar, descriptive anchors |
| SERP overlap test | Same results → same page |
| Content brief | Consistent quality at scale |
| Audit | Update, merge, prune quarterly |

## How It Actually Works

Search engines model topics and entities, not just keywords. A site with many interlinked, high-quality pages covering a subject in depth sends strong signals of **topical authority**, which helps new pages in that topic rank faster. Internal links distribute authority and define the relationship between pages, while pruning weak content raises the average quality of the site — important because quality signals are evaluated at the site level as well as the page level.
